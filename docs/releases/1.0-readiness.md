## Existing verification evidence

The v0.8.3 development state passed 529 unit tests, 5 Rust tests, 12 WASM tests, production build, and root/subpath static smoke checks during development. The full browser suite passed 327 tests before the modal dismissal change. After that change, 36 relevant tests passed across Chromium, Firefox, and WebKit, and the production build passed again.

These results are regression evidence for the current development state, **not** evidence that the requested 1.0 acceptance matrix is complete. Live GitHub authentication, real repository writes, manual screen-reader acceptance, and production deployment were not verified by those mocked browser tests.

## Final release gates

1. Establish v0.9.3 as a tested, committed baseline; preserve intermediate release boundaries.
2. Audit public schemas, migration fixtures, exact Markdown recovery, imports and exports.
3. Audit every publishing write path, authentication/session boundaries, and conflict/partial-failure recovery.
4. Run malicious Markdown, SVG, URL, JSON, workflow and path fixtures; audit dependencies and notices.
5. Complete keyboard, screen-reader, mobile and three-engine acceptance; record any manual checks separately from automation.
6. Benchmark 100 KB, 250 KB, 500 KB and 1 MB documents; test Worker/WASM failure and offline behavior actually supported by the final baseline.
7. Finish onboarding, synthetic examples, documentation index, security/privacy guidance, contribution and release policies.
8. Record resolved and accepted limitations with no known critical data-loss, security, recovery, export or publishing blockers.
9. Only then set 1.0.0, update changelog/release notes, commit and tag, deploy, and verify the live version.

Do not mark a gate passed solely because its documentation exists. Record the command, result, commit and manual verification evidence where applicable.
